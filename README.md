# Bouquet Tool

TRPG中に、演出やRPを良いと思った時に参加者同士で気軽にブーケを投げ合うための、GitHub Pages向け静的Webアプリです。

## 実装済み

- セッション作成
- 8文字のセッションコード自動生成
- 参加URL自動生成・コピー
- 表示名で参加
- 同じブラウザでの再接続
- PL / GM 共通メイン画面
- セッション作成者だけ「セッション管理」を表示
- 他参加者へブーケを投げる
- 自分のカードだけブーケを使う
- ブーケ数 1〜999
- 複数人のリアルタイム反映
- 連打可能（クライアント側キュー＋DB側直列化）
- 同一対象への連打トーストを合算表示
- 履歴（日時 / 操作した人 / 宛先 / ブーケ）
- 使用時は宛先を「使用」と表示
- 履歴領域の内部スクロール
- CSV出力（UTF-8 BOM付き）
- セッション名変更
- セッション終了（関連する参加者・ブーケ履歴を完全削除）

## 構成

```text
bouquet-tool/
├─ index.html
├─ styles.css
├─ app.js
├─ config.js
├─ README.md
└─ supabase/
   └─ schema.sql
```

GitHub PagesはHTML/CSS/JavaScriptを配信し、データ保存・認証・リアルタイム同期はSupabaseを使用します。

## 1. Supabaseの準備

1. Supabaseで新規プロジェクトを作成します。
2. **Authentication > Providers** で Anonymous Sign-Ins を有効にします。
3. SQL Editorで `supabase/schema.sql` を全て実行します。
4. Project Settings / API から以下を確認します。
   - Project URL
   - Publishable Key (`sb_publishable_...`)
5. `config.js` に設定します。

```js
window.BOUQUET_CONFIG = {
  SUPABASE_URL: "https://xxxxx.supabase.co",
  SUPABASE_PUBLISHABLE_KEY: "sb_publishable_xxxxx"
};
```

`service_role` / secret key はブラウザやGitHubへ置かないでください。

### Anonymous Sign-Insについて

このアプリはユーザーにメールアドレスやパスワードを要求しないため、Supabase Anonymous Authを使用します。匿名ユーザーも固有のAuth User IDを持ち、RLS/RPCの権限制御に利用します。

身内利用でも公開URLには第三者がアクセスできるため、必要ならSupabase側でCAPTCHA / Turnstileを追加してください。

## 2. GitHub Pagesへ公開

1. GitHubで公開リポジトリを作成します。
2. このフォルダの中身をリポジトリ直下へ配置します。
3. GitHubの **Settings > Pages** を開きます。
4. GitHub Pagesを有効化します。
5. 公開URLを開きます。

アプリは静的サイトなのでビルド工程は不要です。

参加URLは次の形式になります。

```text
https://USERNAME.github.io/REPOSITORY/?room=ABCD1234
```

## 3. 使い方

### GM

1. 「新しいセッションを作成」
2. セッション名とGM表示名を入力
3. 自動生成された参加URLをコピーして共有
4. メイン画面で他参加者へブーケを投げる / 自分のブーケを使う
5. 右上の「セッション管理」からCSV出力・終了操作
6. セッション終了時は確認後、セッション・参加者・ブーケ履歴を完全削除

### PL

1. 参加URLを開く
2. 表示名を入力
3. ブーケ数を入力
4. 他人の「投げる」または自分の「使う」を押す

## 4. ブーケの扱い

現在のブーケ数は次の考え方です。

```text
受け取ったブーケ合計 - 自分が使用したブーケ合計
```

自分へブーケを投げることはできません。
他人のブーケを使用することもできません。
残数を超える「使用」はDB側で拒否します。

「セッション全体のブーケ」は、全参加者の**現在所持数の合計**です。そのため、誰かがブーケを使用すると減少します。

## 5. 連打と同時操作

画面上のボタンは連打可能です。

- 各クリックは1操作としてキューへ積みます。
- DBには1クリックごとに1件の操作ログを保存します。
- `request_id` で同じ操作の二重登録を防ぎます。
- DB側でも操作者単位のtransaction advisory lockを使い、「使用」の同時処理で残数が負数にならないようにします。
- 同じ相手への連続操作は、右下トーストだけ合算して表示します。
- 別相手へのトーストは最大3件程度を表示します。

## 6. 履歴

画面では最新の履歴から表示します。履歴領域だけがスクロールするため、件数が増えても「CSV出力」「メイン画面へ戻る」は画面下部に固定したレイアウトを維持します。

CSV列:

```text
日時,操作した人,宛先,ブーケ
```

使用時:

```text
2026/08/09 00:13:51,もにょもにょ,使用,5
```

## 7. 補足

- `config.js` のPublishable Keyは公開される前提です。データ保護はRLSとRPC側で行っています。
- Realtimeは小規模な身内TRPG用途を想定してPostgres Changesを使用しています。
- 長期間運用する場合は、古いセッション/匿名Authユーザーの整理方法を別途決めてください。


## 8. セッション終了時のデータ削除

「セッションを終了」を押すと、削除前に確認ダイアログを表示します。

```text
セッションを終了すると、参加者・ブーケ・履歴がすべて削除され、元に戻せません。
必要な場合は、先にCSVを出力してください。
```

確認後、セッション本体を削除します。`bouquet_participants` と `bouquet_events` は外部キーの `ON DELETE CASCADE` により自動削除されます。削除完了後は参加URLの `room` パラメータとブラウザ内の参加者ヒントを消し、参加画面へ戻ります。

※ Supabase Auth の匿名ユーザー自体は、このブラウザアプリからは削除しません。セッションデータ・参加者データ・ブーケ履歴とは別管理です。匿名Authユーザーまで定期削除したい場合は、管理権限を持つサーバー側処理を別途用意します。

## 参加者カード移行（追加改修）

匿名ログインのため、ブラウザのサイトデータ削除・別ブラウザ利用などで同じ人のカードが複数作られる場合があります。
セッション作成GMは「セッション管理」から旧カードを新カードへ移行できます。

- 旧カードの現在ブーケを新カードへ加算します。
- 旧カードは `is_active = false` となり、通常画面から非表示になります。
- 過去の投擲・使用履歴は削除しません。
- 履歴には `カード移行：旧名 → 新名` と移行ブーケ数を追加します。
- GM本人が現在使用しているカードを移行元にすることはできません。

既存のSupabaseプロジェクトへ追加する場合は、先に `supabase/migration_card_transfer.sql` をSQL Editorで1回実行してください。
新規構築時は更新済みの `supabase/schema.sql` のみで構築できます。

## セッション終了

セッション終了は `delete_bouquet_session` RPCを使用し、セッション本体を削除します。
外部キーの `ON DELETE CASCADE` により、参加者・ブーケ操作履歴・カード移行履歴も同時に削除されます。
必要な履歴は終了前にCSV出力してください。
